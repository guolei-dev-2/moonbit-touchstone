# 09轮：GT匹配域与功率裕量修复

沿Touchstone文件、匹配条件、GT查询结果复核后，发现一项根因造成三种错误：先求舍入后的|Γ|，再用它判断无源域、计算1−|Γ|²，可能把微小正功率裕量算大、接受域外有源负载，或把它误报为无耗负载。

## 具体反例与修复

令Γ的binary64分量为`[0.9999999999999999,1.4901161193847655e-8]`，即x=1−2^-53、y=2^-26−2^-79。精确分量平方和给出的正裕量是`3·2^-106−2^-158`，约3.697785493223493e-32。在匹配输出、S21=1且其余S为零时，GT就是该值；旧JS路径却给出约2.220446049250313e-16。

将y增为`1.4901161193847656e-8`，精确裕量为−2^-106，已在允许域外，旧路径仍接受并给正增益。Γ=`[1,1e-200]`也严格在域外，但小虚部平方会下溢，旧路径将负载误报为零功率的无耗负载。

现在直接从实、虚分量计算功率裕量：对有界分量分裂平方的高、低项，用TwoSum浮点展开保留相消余项。单个轴分量等于1且伴随任意非零另一分量时直接判域外，避免其平方下溢改变符号。这些是既有[Priest/Shewchuk浮点展开方法](https://www.cs.cmu.edu/~quake/robust.html)的本地应用，不主张算法原创；没有改全局Complex::magnitude或MoonBit SDK。

已有合同不变：有限Γs满足|Γs|<1，有限Γl满足|Γl|≤1。判断针对解析后的binary64分量；例如十进制`[0.6,0.8]`变为binary64后平方和略大于1，不再因模长舍入而被当成精确单位圆负载。没有任意epsilon或静默投影。合法域内分量继续接受；±1、±i轴上的单位负载仍是零实功率，单位源仍不具正可用功率。GT分母、尺度表示、状态字段及公共API保持。

## 可运行的文件消费

```sh
moon build --target js --release --deny-warn
node tools/touchstone.mjs transducer-gain examples/power-gain.s2p '@examples/power-gain-near-circle.json'
moon test matching_test.mbt --target js --deny-warn
moon test gain_test.mbt --target wasm-gc --deny-warn
```

这里复用08轮合成双向放大器文件，新选项演示近单位圆的合法源；输出保留很小的正增益及有限dB，不把它当成精确零。普通匹配/失配示例与API见[GT使用说明](TRANSDUCER-GAIN.md)。

独立消费者为66次桥接请求，按Fraction的精确binary64分量分类有效域；33个有效点与33个预期拒绝均符合。增益采用四个入射/反射波的精确复数消元，dB参考为160位Decimal，没有复制平方分裂或浮点展开实现。另有3次实际文件CLI：合成文件核对2点；现存且哈希固定的NXP BFU530W模型做2组新GT匹配查询，每组返回98频点、只独立核对索引0/49/97三点。因此合计41个有效点检查，不把返回点数当成已逐点独立验证数。

NXP原S2P、完整模型矩阵和完整98点输出未写入项目/报告或归档；输入身份、选择范围及少量增益参考记录于[独立回执](../evidence/matching-repair-20261028/independent-first.json)。旧的厂商dump/Y/写出集合未重跑；这不是新的设备测量或全部偏置验收。命令和退出码见[检查记录](../evidence/matching-repair-20261028/CHECKS.json)，失败复现保留。公共mbti与桥接/Node实现不变；05—08既有其他生产源码保持。

本轮修复匹配域和功率裕量，不扩展主动终端增益、频变Γ输入、匹配综合或非线性模型。极近反馈奇点的binary64相消精度限制仍存在，有限GT仍不等于稳定性认证。
