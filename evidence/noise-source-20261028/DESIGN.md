# Round 20: noise-source power margin repair

Scope: one existing consumer chain, two-port Touchstone noise records to `Document::noise_figure` / the existing `noise` CLI. No new feature, API, command, format or third-party runtime.

Evidence before editing: `BASELINE.json` records three actual file CLI processes using the pinned old release bridge. Matched source gives 1.0000000000000002 dB. For binary64 source `(1-2^-53, nextDown(2^-26))`, exact rational `1-re²-im²` is positive; independent 160-digit direct noise-parameter evaluation gives 320.34118276990307 dB but the implementation returns 162.55619765854985 dB. `(0.6,nextDown(0.8))` should give 164.7746851547134 dB and also returns 162.55619765854985 dB. The input has valid PSD noise covariance and succeeds for the ordinary matched control.

`DOMAIN-BASELINE.json` records the same first source with its imaginary component one representable value higher, `2^-26`: exact margin is `-2^-106`, strictly outside the legal source disk, but the old CLI incorrectly accepts it. These are consequences of one cause: domain and denominator use a rounded complex magnitude followed by `1-g*g`.

Repair only `noise.mbt`: obtain the source power margin from the existing private package helper `gain_margin`, require it to be strictly positive, and use it as the denominator's source-power factor. The helper already computes bounded binary64 square expansions and retains cancellation and exact unit-axis domain signs. Leave the helper, covariance/parameter transformations, noise circles, interpolation, parser, other RF algorithms and Node bridge unchanged. Domain remains finite complex Gamma with exact `1-re²-im²>0`; no tolerance clamp, epsilon regularization or reduced legal domain.

Verification: three new public-API regression tests on JS/Wasm-GC/native; one independent stdlib Fraction/Decimal file consumer pass (six real Node CLI processes: three legal controls and three invalid sources). Compare ordinary matched output byte-for-byte with baseline, compare other covariance/circle payloads exactly, and require true-unit/outside/axis-plus-subnormal sources to reject via the existing domain error. New tests are numerical boundary regressions, not copies of the implementation. Regenerate interfaces, require old interface bytes unchanged, strict all-target check, formatting and one local package. Preserve baseline failures and old evidence; do not rerun historical suites or add vendor inputs.

Reference: the existing ecosystem provides the same conventional noise-parameter relation, rather than a novel RF algorithm. [scikit-rf noise-circle documentation](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.Network.nf_circle.html) states `(F-Fmin)|1+Gamma_opt|²/(4Rn/Z0)=|Gamma_source-Gamma_opt|²/(1-|Gamma_source|²)`. The oracle evaluates this relation from input parameters with exact binary64 fractions and 160-digit decimal arithmetic, independently of production magnitude/covariance code. No scikit-rf double-precision boundary result is used as the near-circle oracle.
