# Round22: a real one-port metric module/file consumer

Scenario: a caller reads a finite one-port impedance sweep and displays return loss and VSWR without confusing a matched zero-reflection point, full reflection, or active reflection. The existing public `parse -> network_only -> metrics(0,0)` and `metrics` file command already implement this; a second algorithm or a new API would duplicate them. For output=input=0, the generic transmission/insertion fields also refer to S11, not a physical two-port transmission measurement.

Coverage reviewed: analysis_test.mbt checks ordinary S-space Option/state fields; tools/verify-reference.py compares ordinary metrics against scikit-rf; tools/check-cli.mjs includes invalid metric ports but no full state-by-state paired public-module/file JSON consumer in the inspected set. This is a bounded evidence gap, not proof that the metric core is defective or globally untested. Rounds20 noise and21 cascade are excluded.

Chosen work: add one executable pure MoonBit example importing the public module and parsing an embedded valid Touchstone2.1 Z sweep (50ohm reference; five frequency samples with Z=0,50,150,-150,50+j50ohm). It emits the exact input text and its `metrics(0,0)` JSON. A stdlib-only development verifier writes exactly that text to a real .s1p file, runs the unchanged file CLI once, requires the complete parsed JSON array to equal the module result, and checks every row against independent scalar Gamma=(Z-50)/(Z+50), |Gamma|, -20log10|Gamma| and the existing finite/infinite/active VSWR contract. No new root tests or production code unless a concrete failure appears.

Acceptance: one actual public-module JS execution and one actual Node file CLI execution; five paired samples; finite fields within2e-12 absolute or relative; exact flags, frequency/order and omitted Option keys. Zero reflection must have infinite-loss flags and omitted dB values; unit reflection must omit VSWR with infinite state; |Gamma|>1 must omit VSWR with active state. The physical scalar oracle uses input ohms, not production conversion/magnitude or JSON serialization. Preserve any failure before fixing it. Finish with formatting, regenerated interfaces, strict all-target compilation appropriate to the new example, one package and all-entry source/module readback. Do not rerun historical tests, near-circle or cascade verification, or claim new core/math/API work if none is needed.

Compatibility: only a new example, independent development verifier and user guidance. Keep every existing .mbt, generated old interface, Node bridge/CLI, noise source exact-margin helper and metadata unchanged. README/29-line proposal may add an ordinary usage sentence; no round counter/pass ledger as the new introduction. No manufacturer model, runtime dependency, external installation or feature claim.

Ecosystem/candidates: bounded searches `site:mooncakes.io S parameter VSWR RF`, `site:mooncakes.io RF network`, `MoonBit VSWR`, `MoonBit S-parameters` did not identify a relevant package in returned surfaces; lexical RF/network API matches were irrelevant. This is not an absence/uniqueness claim. A new VSWR/impedance API was rejected because the local API already suffices. The official [scikit-rf zl_2_swr](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.tlineFunctions.zl_2_swr.html) documents the same impedance/Gamma/VSWR relation; its Network has s_db/s_vswr. The difference here is the native MoonBit file consumer and explicit existing state/Option convention, not a new RF formula. No third-party library is installed or run, and the active-domain state is checked against this project's documented contract rather than blindly copying a negative raw VSWR formula.
